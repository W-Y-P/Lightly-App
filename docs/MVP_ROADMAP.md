# MVP 开发路线图

首发渠道：微信小程序。后端 API 和领域模型设计为多端复用，未来可扩展至 iOS / Android。

## 阶段 0：原型确认

目标：用 Mac 本机 demo 确认产品结构、文案、数据展示和核心计算。

交付：

- 今日面板
- 餐段记录
- 运动记录
- 星星规则
- 趋势图
- 计划页
- 积分和高级设置占位

验收：

- 用户一打开就能理解今天还能吃多少、是否接近目标
- 至少两个餐段记录后可以判断是否达标
- 趋势页能看到体重点、移动平均线和计划线

## 阶段 1：领域模型和公式

目标：把计算规则从界面中抽出来，变成可测试的业务模块。

交付：

- BMR/TDEE 计算
- 目标缺口计算
- 建议摄入计算
- 实际缺口计算
- 星星规则
- 积分规则（达标 +1 积分，1 积分 = 1 次额外拍照识别）
- 碳蛋脂目标计算
- MET 运动估算
- 体重移动平均
- 代谢校准初版

验收：

- 所有核心公式有测试样例
- 同一组输入在后端、小程序、未来 iOS/Android 中可得到一致结果

## 阶段 2：后端 API 骨架

目标：搭好自建后端的主干。

交付：

- Node.js + TypeScript + Fastify
- Postgres + Prisma
- 用户、计划、餐食、运动、体重、积分、校准表
- API 路由
- 错误处理、日志、基础鉴权

验收：

- 本地可以创建计划、写入记录、读取今日摘要
- 数据库 migration 可重复执行
- 删除账号流程可跑通

## 阶段 3：食物库和 AI 识别

目标：让拍照和自然语言录入能返回可修改的估算结果。

交付：

- 高频中国食物库 1000-2000 条起步
- 食物别名和分类
- 文本解析接口
- 图片识别接口
- 食物库匹配和 AI fallback
- 每日免费 1 次拍照识别 + 积分兑换额度控制

验收：

- 常见家常菜、外卖、饮品能返回结构化结果
- 用户确认前不入账
- 不长期保存照片
- 每天免费识别次数和积分额度正确

## 阶段 4：微信小程序 MVP

目标：做出可体验的微信小程序版本。

交付：

- 微信授权登录
- Onboarding
- 今日页
- 记录页
- 趋势页
- 计划页
- 我的页
- 本地缓存
- 游客模式
- 积分体系
- 相机 / 相册权限调用

验收：

- 不登录也能完整使用核心功能
- 登录后能同步数据
- 拍照识别额度正确（每日免费 1 次 + 积分兑换）
- 本地缓存和游客模式正常运作

## 阶段 5：合规和上架准备

目标：准备微信小程序首发。

交付：

- 隐私政策
- 用户协议
- 账号删除入口
- 微信小程序类目选择和备案
- 隐私保护指引配置
- 健康数据和未成年人风险提示文案
- 提审材料准备

验收：

- 小程序内可以发起删除账号及相关数据
- 隐私政策清楚说明健康数据、体重、照片、AI 处理、保存时间
- 不把健康数据用于广告或营销画像
- 提审材料齐全，可提交审核

## 阶段 6：内测和迭代

目标：验证真实用户是否愿意持续记录。

指标：

- D1/D7 留存
- 每日记录完成率
- 拍照识别使用次数
- 手动记录使用次数
- 体重记录频率
- 星星达成率
- 积分获取和消耗平衡
- AI 结果修改率

重点观察：

- 用户是否理解热量缺口
- 拍照估算是否足够可信
- 饮品和外卖是否是最大误差来源
- 用户是否愿意记录两顿以上
- 代谢校准建议是否被接受
- 积分激励是否能驱动持续使用

## 未来路线：iOS / Android 原生

当小程序验证通过后，可启动原生应用开发：

- 复用后端 API 和领域模型
- 复用视觉规范和交互设计
- 接入 Apple HealthKit / Google Fit
- 探索增值服务方案

## 首版范围

必须有：

- 计划生成
- 饮食记录
- 运动记录
- 体重趋势
- 代谢校准建议
- 星星激励
- 积分体系（每日免费 1 次拍照 + 达标换积分）
- 游客模式
- 微信登录
- 账号删除

暂缓：

- 社区
- 食谱商城
- 私教聊天
- 扫条码
- 复杂训练计划
- iOS / Android 原生应用
- Apple Watch 独立 App
- 完整国际化
- VIP / 订阅 / 付费功能

## 最大风险

- 餐食识别误差导致用户不信任
- 小程序审核和备案准备不足
- 用户记录负担过重
- 积分体系过于单薄，难以驱动持续使用
- 未成年人和健康数据处理不够谨慎
- 食物库维护成本高

## 近期建议

1. 先用 demo 确认首页和记录流程。
2. 再把核心公式抽成测试模块。
3. 同时准备食物库字段和 100 条样例数据。
4. 开始后端 API 骨架。
5. 进入微信小程序客户端开发。
